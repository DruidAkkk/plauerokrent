# База данных rentbot — записка для разработчика

## Выбор СУБД (важно)
Две разные БД в проекте, не путать:

1. **У клиента (self-hosted воркер) — SQLite.** Один файл, WAL-режим. Ставится в ноль действий, не надо держать Postgres у неквалифицированного продавца. Нагрузка одного магазина копеечная — SQLite с запасом. Это в `storage.py`.
2. **На нашем сервере (лицензии, общий ЧС, телеметрия) — Postgres.** Тут многопользовательская нагрузка и несколько клиентов пишут одновременно. Схему этого сервера ниже НЕ описываю — это отдельный маленький сервис (FastAPI + Postgres), делаем на этапе платного запуска.

Если принципиально хочется Postgres и у клиента — можно, но тогда тащим его в docker-compose воркера. Не рекомендую для MVP. Абстракция хранилища (класс `Storage`) позволяет сменить бэкенд, не трогая движок, так что переезд SQLite→Postgres потом дешёвый.

## Схема (клиентская БД, SQLite) — см. storage.py
Полная DDL в `rentbot/storage.py` (константа `SCHEMA`). Таблицы:

### accounts — пул арендных аккаунтов
- `id, game` (метка пула: cs2/dota2/faceit/…), `login`
- `password_enc, shared_secret_enc, identity_secret_enc, mafile_enc` — **всё шифруется** (Fernet, ключ из мастер-пароля через scrypt; см. `vault.py`). В БД секретов в открытом виде нет.
- `proxy` — прокси на аккаунт (антибан Steam/Faceit)
- `state` — free / rented / rotating / resting / quarantine / paused
- `rest_until` — таймстемп конца «отдыха» между арендами
- `note, tags` (tags — JSON-массив: "faceit_verified","prime",…)

### lots — привязка лота площадки к пулу
- PK (`marketplace`, `lot_id`)
- `game` — какой пул обслуживает лот, `hours` — срок за одну покупку
- `rotation` — auto / semi / manual (как возвращать аккаунт по этой игре)

### rentals — аренды (ядро)
- `id`, `marketplace`, **`deal_id`** — id сделки площадки
- **UNIQUE(marketplace, deal_id)** — это ключ идемпотентности: одно и то же событие из WebSocket и из страховочного опроса не создаст две аренды. Вставка дубликата ловится и игнорируется (см. `insert_rental` → возвращает None).
- `lot_id, buyer_id, buyer_name, chat_id, account_id`
- `state` — queued / active / ended / cancelled
- `started_at, ends_at, price, warned` (предупреждение «15 мин» отправлено), `codes_issued` (лимит кодов Guard на аренду)
- индекс `(state, ends_at)` — для быстрого тика планировщика

### blacklist — ЧС арендаторов
- PK (`marketplace`, `buyer_id`), `reason`, `created_at`

### events — журнал действий
- `ts, kind` (issue/code/extend/end/rotated/rotate_fail/queued/…), `rental_id, account_id, data`(JSON)
- нужен для статистики и чтобы понимать, что сделал бот (разбор споров)

## Ключевые моменты, на которые смотреть
1. **Атомарная выдача аккаунта** — `claim_free_account()` делает `BEGIN IMMEDIATE` + возвращает отдохавших в пул + берёт первый free и ставит rented в одной транзакции. Это чтобы два параллельных заказа не схватили один аккаунт. При переезде на Postgres заменить на `SELECT … FOR UPDATE SKIP LOCKED`.
2. **Очередь** — если свободных нет, аренда создаётся в state=queued; при освобождении аккаунта `_drain_queues()` раздаёт очередь по FIFO (`queued_for_game`).
3. **Идемпотентность** — вся защита от дублей висит на UNIQUE(deal_id). Любой обработчик события сначала пытается вставить, при None — выходит.
4. **Таймеры переживают рестарт** — состояние аренд в БД, при старте воркера `tick()` просто находит просроченные (ends_at<=now) и завершает их. Планировщик (APScheduler) дергает tick() раз в N секунд; БД — источник правды, не память.
5. **Статистика** — `stats(since)` считает выручку и загрузку каждого аккаунта в % (busy-время / период). Для продавца это главная метрика «какой аккаунт окупается, какой простаивает».

## Что НЕ хранить в БД
- Секреты в открытом виде (только *_enc).
- Мастер-ключ шифрования (он в env или вводится при старте, живёт в памяти).
- Логины/пароли в таблице events или в логах (в `vault.mask()` есть маскировка для логов).

## Тесты
`tests/test_engine.py` гоняет весь цикл на in-memory SQLite (`:memory:`) с фейковыми площадкой/Steam — 7 сценариев, включая идемпотентность и гонку за аккаунт. Запуск: `python3 tests/test_engine.py` (нужен только пакет `cryptography`).
